# 006 — Stand on the body

- **Status**: TODO — supersedes 005
- **Commit**: 8419849
- **Severity**: HIGH
- **Category**: Architecture & failure modes
- **Estimated scope**: `mount.ts`, `place.ts`, `gateCss.ts` and its three sheets; most of the selector guard system becomes deletable

## The claim

This extension consumes three things from GitHub, and two of them are already read
deterministically. Page identity comes from the URL, parsed by the same functions the
screens use. Data comes from GitHub's own `page_data` JSON, decoded against schemas that
say out loud when something changed. Neither can be broken by a redesign, because both
are the machine contract GitHub's own pages run on.

The third — where to stand and what to hide — is read from their *human* presentation:
class names, aria-labels, layout boxes. That is the only non-deterministic read left,
and it is where every selector, gate, band, probe, audit and canary in this repository
comes from. All of that machinery exists to watch a dependency we chose.

Drop the dependency. Every screen already replaces the whole page — content, bar and
nav — so the mount point does not need to be *their* region. It can be `document.body`,
which is the HTML specification's, not GitHub's.

## Verified live, 2026-08-31

Route metadata is on every page type, generated by their router:

```
/                                     dashboard / index
/pulls                                dashboard_surface_inbox / index
/notifications                        notifications_v2 / index
/:user/:repo                          files / disambiguate
/:user/:repo/issues                   issues / index
/:user/:repo/pull/:id                 voltron_pull_requests_fragments / pull_request_layout
```

These names move when GitHub re-architects a page — `notifications_v2`, `voltron_*` —
which is when the extension has real work to do anyway. They never move for a copy edit
or a locale. The URL alone already decides identity today; the meta is a second,
deterministic proof where one is wanted, and the honest replacement for the sign-on
wall's `loadedWhen` selector.

`body`'s children are a flat handful: GitHub's one page wrapper, two `sr-only` nodes,
and whatever extensions have added. Hiding by position at that level takes their whole
page in one move.

## The mechanism

1. **Stand**: the container is appended to `body`. `findSlot`, `regions`, `fallback`
   and the retry machinery around them go. The slot cannot fail to exist, cannot be
   replaced by their React, and is never inside a `main` their own rules hide — the
   whole `widths.css` class of fault disappears with it.
2. **Hide, steady state**: `hideTheirs` aimed at `body` — mark what stands there at
   takeover, ours excepted. JS marking, not a blanket CSS rule, for two residents the
   probe found: our own toaster and hover cards portal to `body`, and so do other
   extensions. A blanket rule would hide both.
3. **Hide, pre-reveal**: one static rule, `html[data-gitquiet-page]:not([data-gitquiet-revealed])
   body > *:not(#gitquiet-root)`, applied at `document_start` from the URL. Flash cover
   only, lifted on reveal or give-up, and safe to be blunt: at that moment nothing else
   of ours or anyone's is on the page yet. 005's stages/bands refinement, one level up.
4. **Identity**: `owns(path)` stays as it is. The wall reads
   `meta[name="route-controller"]` instead of `main:has(div.org-sso)`.
5. **Give-up**: unchanged and still fail-safe — reveal, and the reader has GitHub whole.

## What dies

`regions`, `fallback`, `stages`, `bands` and `soft` on every place; `findSlot` and the
slot re-finding observer; the three generated sheets and `build-gates.ts`; the DOM
probes' selector-hunting purpose; and the entire guard system built on 2026-08-31 —
`gateAudit`, the canary and its manifest, the hygiene test, the freshness ledger. That
system was scaffolding: it watched the presentational read while it existed. The wire
drift check (`bun run drift`) stays, because the data contract is the one dependency
that remains and it already has its watcher.

## What stays, named and known

- `theirNav` still reads the repository tabs out of their hidden header for our bar.
  The one presentation-read left. It survives this change unmodified — the header is
  hidden, not removed — and is replaceable later from data.
- Their page keeps running underneath, deliberately: the `alive.github.com` socket is
  still how change reaches us. Hiding at `body` level does not touch that.

## Order of work

`mount.ts` is the most measured file in the repository; every comment in it is a bug
that happened. So: one screen first, behind its own place entry — home, the page that
bit us — live-verified with the existing QA scripts, then the rest place by place, then
the deletions last, once nothing reads what they guarded.
