Issues inside the Courts

Shape A is settled: the top level stays whose move is it, and both kinds of work live inside it. What is open is how an issue row is drawn there. Every row below is real — scraped from your Working Set on github.com, dark theme, live tokens.

Your Move holds 1 pull request and 3 issues; Waiting On Others holds 9 and 15. So this is not a corner: most of what the Courts count is already issues.

A — as built today

shipping

The issue takes the pull request's grid and leaves four tracks empty: review, checks, comments, diff. The hatching marks them. Nothing is wrong per row, but the column nobody fills reads as missing data rather than as a different kind of thing.

B — the issue row stops pretending

recommended

Same Court, same order, same count. The issue keeps the first four tracks it shares with a pull request — face, state, title, repository — and then spends the rest of the row on what an issue actually has: its labels, and its age. Nothing is blank, because nothing is missing. The blue ring says issue at the same place the green one says pull request.
